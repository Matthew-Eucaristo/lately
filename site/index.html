What just happened on my Mac?
And what mattered.

A terminal flashed. An app opened by itself. macOS said “Background Items Added”. The Mac restarted overnight. The answers are already on your Mac, buried in 14,000 log lines a minute. lately knows which few hundred matter and turns them into a short timeline. One command. No root, no daemon, no AI.

$ brew install matthew-eucaristo/tap/lately

Classified, not dumped

Console shows everything. lately shows what matters.

Eight narrow log lenses, crash reports, boot and power records, install receipts and the folders software uses to start itself. 42 rules put every event at one of five levels, group bursts into one row (×3), hide Apple's own noise and stop marking things NEW once you have seen them.

  • ✖ CRIT act now
  • ▲ HIGH look at even one
  • ● MED look if unexpected
  • ○ LOW context
  • · INFO hidden by default

Glyphs and words always sit next to colour, and NO_COLOR is honoured.

The questions it answers

For the moments your Mac does something on its own.

“A terminal window just flashed.”

With sudo lately capture, a shell that an osascript, launchd job or cron job started, and that lived under 2 seconds, becomes an EXEC row. A shows the chain that started it. A parent that exited before capture is shown as chain broken, never guessed.

launchd (1)   Apple
└─ com.foovpn.helper (4300)   Dev ID ABCDE12345
   └─ osascript (4321)   Apple
      └─ zsh (4322)  zsh -c curl -fsSL https://… | sh  ◀

“Background Items Added.”

Every new launch agent, daemon, login item, system extension, cron entry, SSH key or shell-startup change becomes a row, with its signer and the install that wrote it. Persistence rules carry MITRE ATT&CK IDs.

▲ HIGH  PERSIST  Launch daemon added: com.foovpn.helper
WHY  Written during the Foo VPN install (Installer)
DO   Expected? press a. Not expected? launchctl bootout …

“Why did my Mac restart overnight?”

Apple silicon logs no shutdown cause code. lately combines wtmp, the panic breadcrumb, DumpPanic's check, shutdown-stall reports, the watchdog record, recent updates and the last power line into one verdict.

VERDICT  ● Hung shutdown
  ✓ watchdog  a watchdog reset (wdog)
  ✓ stall     1 shutdown_stall report

“It keeps crashing when I do this.”

Press f and reproduce it. One log stream per lens, plus crash reports, installs and launch items rechecked every 5 s. New rows land on top in green; a repeat bumps its ×N in place.

since 17:01 ● live 8s
▲ new HIGH at 17:16:35: shop-app crashed ×4

“What did I just allow?”

Screen Recording, camera and microphone answers, Gatekeeper checks and XProtect detections. Rows read from log text Apple does not document are marked ≈approx.

▲ HIGH  PERMIT  com.meetapp.desktop allowed Screen Recording
        NEW ≈approx

“Did something happen earlier?”

t reaches one step further back (5m … 7d) and reads only the span it adds; T comes back without rereading. The header says how far back the log really reaches.

window 5m 15m 30m 1h 2h 3h 6h 12h 1d 2d 3d 7d

An event card for every row

Not just what happened. Who, why, and what to do.

Press ⏎ on any row. Every card has the same sections, then the subject's own activity over the window and its related findings: the same process, its parent or children, the launch item that runs it, the install that delivered it, the same developer. Cards suggest commands; they never run them.

  1. What happened, in plain words, with the path.
  2. Who: the signer, the team, and whether this Mac has seen it before.
  3. Why: the evidence behind it, such as the install that wrote this launch daemon.
  4. Matters: why this kind of event deserves a look, with its MITRE ATT&CK ID.
  5. Do: the exact next step. Mark it known with a, or remove it yourself.
  6. Raw: the file, or the exact /usr/bin/log show command to check it yourself.

lately why-restart

One verdict. With the evidence.

Apple silicon Macs log no shutdown cause code, so lately weighs everything that is left and says exactly one of:

  • ● clean restart
  • ● update restart
  • ● kernel panic
  • ● hung shutdown
  • ● unexpected, with the likely cause

When the verdict is inferred, it says so. Press R in the demo above to see this one live.

Honest about blind spots

A tool that silently shows less is worse than one that admits it.

Every limit is named on screen, every run. ? lists all of them.

The log is short

macOS keeps a few days at most, and log stats overstates it. lately reads the oldest file in the log store and prints how far back it really reaches.

macOS redacts

Many log fields read <private>. lately counts them instead of pretending they are not there.

Short-lived commands need capture

Without sudo lately capture you see that Terminal launched, not the 200 ms shell inside it.

Restart causes are inferred

No shutdown cause code on Apple silicon, so the verdict says “inferred”.

Some rows are approximate

Permission and Gatekeeper rows come from log text Apple does not document, and they carry ≈.

No network history exists

Recording which app talked to which host needs a firewall extension such as LuLu. lately net shows live connections only.

ⓘ 12 field(s) were redacted by macOS as <private>.
ⓘ Commands and parents of short-lived processes need capture: sudo lately capture

What it reads

Evidence your Mac already keeps, read by Apple's own tools.

Everything below is readable by a normal user. lately runs /usr/bin/log, pmset, last, codesign, systemextensionsctl, lsof, nettop and ps, or reads files directly. No frameworks, no cgo.

Unified log, 8 lenses

RunningBoard launches, TCC decisions, Gatekeeper, XProtect Remediator, Background Task Management, DumpPanic, jetsam and shutdown cause, log erase.

Diagnostic reports

Crashes, faults, hangs, jetsam, resource reports, shutdown stalls and panics, from one JSON line per .ips.

Boot records

kern.boottime, last reboot, last shutdown and the DumpPanic breadcrumb.

Power log

Sleep, wake, dark wake and failures, and whether the Mac was on AC before a restart.

Installs

InstallHistory, install.log and Homebrew logs, so a new background item points to the install that wrote it.

Persistence

Launch agents and daemons with their signatures, crontab, shell startup files, authorized_keys and system extensions.

Live network

lsof and nettop: what your processes are connected to right now.

Elevated: sudo lately capture

Apple's eslogger as a child process for exec, fork, exit, background items, TCC, XProtect and more. In memory only, and it stops when you quit.

Privacy & footprint

Safe to run. Safe to paste.

  • Read-only. lately never changes the system, installs or schedules nothing, and never asks for your password. Cards print commands; they never run them.
  • No daemon. It runs only while you have it open. Quitting stops everything it started, log stream children included.
  • No network, no AI. It sends nothing anywhere.
  • One small file. The baseline holds salted SHA-256 hashes and dates: no names, paths or URLs. lately forget deletes it.
  • Light. Idle: 0.15% CPU and 14 MB. Following: 0.30%, plus eight log stream children at 0.1–0.4% together. Child tools run at nice 10.

Questions

Fair questions.

Is this an antivirus?

No. lately is a diagnostics tool: it explains what happened, with evidence, and suggests what to do. It removes nothing and changes nothing. It does surface XProtect detections and the persistence tricks malware relies on, which makes it a good first look before you reach for anything heavier.

Why not just open Console?

Console shows everything, about 14,000 lines a minute, mostly Apple talking to itself. lately reads eight narrow slices of the log plus evidence Console does not show at all (crash report headers, boot records, install receipts, launch items), classifies it with 42 rules and groups the rest away.

Does it need sudo?

No. Everything in the timeline is readable by a normal user. Only sudo lately capture is elevated, for short-lived processes and their command lines, and it runs only while you keep it open. lately never asks for your password itself.

Does it send anything anywhere, or use AI?

No network connections, no telemetry, no AI. The classification is 42 readable YAML rules you can tune without touching Go. This page loads nothing from third parties either.

What does NEW mean, and what does it store?

NEW means this Mac has not seen the subject before. To know that, lately keeps one file of salted hashes and dates, never names or paths. The first run marks nothing NEW and says so. --no-baseline runs without it; lately forget deletes it.

Can I share the output?

Yes, that is what --md, --json and the e export are for. They are redacted by default; --no-redact shows real names when you need them.

Linux or Windows?

macOS only for now. The sources sit behind a cross-platform interface, so a port is a new package beside the macOS one; rules and views stay.
